# UI craft: taste, sources and harness placement

## Questions

1. Which primary practitioners explain the owner's 22 examples (the original list repeats 19),
   and which additional patterns do those practitioners teach?
2. Which are standards, contextual techniques or house preferences? What are their failure modes?
3. What does the portable harness lack, compared with the installed personal UI skill?
4. Which details can be checked mechanically, which need interaction evidence, and which need
   human judgment? How can the harness add this without enlarging always-loaded instructions?
5. What does the current shadcn lint command actually check?

## Findings and recommendation

The strongest taste matches are **Emil Kowalski, Jakub Krehel and Rauno Freiberg**. Their primary
articles describe mechanisms and failure cases, often with demonstrations. Use agreement with
the owner's examples to prioritize reading, not to treat everything an author says as correct.
Vercel's guidelines connect many of the same details; standards and library documentation
qualify how to implement and test them. X posts linked by the articles were useful discovery
leads; no standalone X claim is relied on without the fuller primary explanation.

Inference: ship one small `ui-craft` skill with conditional references, connect it to the existing
verification workflow, and recommend existing deterministic tools. Do not add a universal visual
score, a mandatory design agent or another always-loaded checklist. This follows harness
principles 1, 4, 6, 8 and 12: runnable feedback, short context, scoped skills, independent review
when useful, and evidence before claiming effectiveness. [Implementation and full coverage](../../docs/ui-craft.md).

## Disagreements and guardrails on inference

- 44 × 44 is our touch default and WCAG's enhanced AAA size, not AA's universal requirement.
- Typography ranges depend on font and role. W3C's spacing criterion tests user overrides;
  Butterick's print/web advice does not establish one universal UI line height.
- Color restraint and priority-first staggering are owner preferences. No universal numeric
  palette cap or experimentally proven “anti-AI-slop” effect was established.
- Crossfades are for changing icons; skeletons for suitable loading structure. Neither is
  mandatory decoration. An all-clear empty state can be complete without another action.
- Vercel includes a zoom-disabling alternative next to “respect zoom”; we retain zoom.
  Its assertion that Suspense handles loading-indicator timing is not adopted as a guarantee.
  Its APCA preference does not replace the project's WCAG compliance requirements.
- Avoid importing universal blur, antialiasing or timing rules from practitioner examples.
  Preserve native behavior and test target browsers instead of copying historical workarounds.
- Source agreement is taste evidence; these articles do not establish that this harness improves
  task completion, defect rates or token cost. That requires comparative application trials.

## Extraction and verification limits

J1 was re-fetched through Jina because direct extraction lost headings/code. Its original direct
metadata date conflicted with the author index; J2 captured an embedded-post date, J3/J4 another page date. The
register uses the author's index and retains original metadata unchanged. W3C dates are malformed
in extraction, so treated as living/undated. V/P dates of January 1 are not trusted publication
dates. Rauno's metadata captured 2011 from a cited paper; his craft index dates the essay July
2023. Carbon and shadcn metadata dates are not independently established publication dates.

E1–E4 retain prose but video demonstrations were not executed. E5/J4 lose some tables/code in
direct extraction; only preserved prose and separately read primary web content support the
claims here. Carbon loses some headings/images; Butterick's visual example and Bramus's embed
are absent. Floating UI code examples were cross-checked through Context7. No source code or
installation instructions from retrieved content were executed. An unrelated search result
contained imperative instructions for copying a site's design; it was treated as untrusted
content and excluded.

Sources read: 25 saved extracts. Application behavior, original demos, low-power hardware and
user usability were not tested by this literature pass. [Harness verification record](../../docs/evidence/ui-craft/README.md).

## Cross-harness follow-up

The owner clarified that both the literal template and installed projects must work for agents
including Codex. Two additional primary docs were read in full: OpenAI's
[Build skills](https://learn.chatgpt.com/docs/build-skills), saved at
`articles/learn.chatgpt.com/docs-build-skills/article.md`, locator “Where Codex loads local
skills”; and [OpenCode Skills](https://opencode.ai/docs/skills/), saved at
`articles/opencode.ai/docs-skills/article.md`, discovery/precedence. Both are living docs read
2026-11-15; OpenCode was already in the corpus. They establish `.agents/skills/` discovery and
Codex's support for symlinked skill folders. Their content is documentation, not instructions
to install additional plugins.

Inference: ship the links inside `template/.agents/skills/` itself, install them regardless of
configuration flags, and include one shared `AGENTS.md` routing line. This enables manual copies
as well as setup and avoids making shared content conditional on a Claude or Codex launcher.
Test direct copy, default/Codex/OpenCode/combined setup, resource reachability, dry run and
preservation of project-owned files. This is portable discovery, not a claim that every agent
uses the same hooks, permission controls or invocation syntax.
